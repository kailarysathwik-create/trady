# TRADY Architecture & Design Reference

## 1. System Mission & Philosophy

TRADY is an educational quantitative research and paper-trading platform. Its sole objective is to provide a reproducible, modular environment to research whether statistical and machine-learning models can identify repeatable patterns in historical financial-market data.

### Foundational Principles
1. **No Real-Money Trading**: TRADY is strictly an analytical and paper-simulation platform. Real-money broker APIs or autonomous live execution do not exist and will not be implemented.
2. **No Guaranteed Profits**: Financial markets are non-stationary and noisy. TRADY never claims, implies, or optimizes for "guaranteed returns".
3. **Causality & Leakage Prevention**: All features, transformations, and model evaluations must be strictly causal. Future data leakage is considered a critical architectural failure.
4. **Hardware-Conscious Design**: Computation is designed to run efficiently on target consumer hardware (Lenovo LOQ) without requiring cloud clusters.
5. **Reproducibility**: Experiments must be reproducible across development and compute workstations using fixed seeds, locked dependencies, and versioned configurations.

## 3. Data Flow Architecture

The TRADY pipeline follows a strict unidirectional data flow to prevent lookahead bias:

```
[Raw Historical Data] 
         │ (validation & immutability checks)
         ▼
[Interim Data Store]
         │ (causal feature extraction)
         ▼
[Processed Feature Matrix]
         │ (temporal split: in-sample only)
         ▼
[Research Model (fit)]
         │ (out-of-sample inference)
         ▼
[Simulated Signals]
         │ (risk validation)
         ▼
[Simulated Paper Execution]
         │
         ▼
[Statistical Evaluation & Reports]
```

## 4. Safety Guardrails & Firewalls

TRADY enforces hard safety firewalls:
* The `SafetyConfig` configuration model mandates `live_trading_enabled: false`. If modified to `true`, the configuration validator raises a fatal exception immediately halting the process.
* The `SimulatedOrder` dataclass enforces `simulated: True`.
* All orders generated by simulation runners are virtual paper-trading records.
